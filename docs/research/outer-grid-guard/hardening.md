# Guard-shell regression evidence

The production rendering code is unchanged from `975d99e51`, whose tree matches the completed Linux timing job. Commits `7f908eae2` and `61a12d8c2` add tests. The tests run the real Vulkan renderer with deterministic settings and synchronization validation.

## Behavior and bounds

The two light-volume test classes have 29 cases. They check camera motion across the outer snap, the fade endpoint at every snap phase, both walking directions, camera cuts, shell occlusion, a sunlit shell reflector and the light-list boundary. They also execute the production shader layout functions for every cell and direction, read every transport direction and filtered lobe through the final dispatch cells, and measure the captured area of a small cube.

The cube-area fixture distinguishes outer cells populated by restriction from those rasterized directly. Its expected 1,536 surface units come from six faces of a 0.25 m cube: 0.375 square metres, at 4,096 units per square metre in the outer grid. The opposite-face fixture compares mirrored scenes near the outer fade, where the receiver needs cell indices beyond 15.

The raw bounds and the Vulkan minimum limits are in [the research report](README.md#bounds-and-vulkan-requirements). These proofs complement sampled rendering tests. Normal validation cannot establish the absence of shader array accesses beyond their declared bounds.

## Coverage

All 29 cases pass in Checked and all 29 pass in Release on the restored source. Checked uses optimized code with contracts enabled. Both runs collect coverage. The union covers all 24 instrumented changed C# lines and all 6 changed C# branches in `LightVolumePass`: 24/24 lines and 6/6 branches, with no uncovered changed line or partial changed branch. This is coverage of changed executable C# lines, not the whole renderer.

There is no earlier coverage measurement for comparison. [The changed-line output](evidence/coverage/changed-lines.txt), test logs and compressed raw Cobertura reports are retained in [the coverage evidence](evidence/coverage/).

The .NET collector does not instrument GLSL. Shader evidence comes from real rendering, the probes that execute production layout functions and read production fields, the mutation table, and the dispatch/address bounds in the research report. There is no shader line-coverage percentage.

## Mutation method

Every mutation ran through `tools/mutate.py`, which builds the mutated production shader or C# assembly, runs the listed tests, restores the original bytes and rebuilds the clean output. No mutation was edited, built and restored by hand. Recovery removed only the interrupted G14 after checking the saved input SHA-256 and the exact mutation diff.

The final table has one result per mutant. The first run covers all 27 mutations. Targeted reruns use the expanded tests and replace the earlier result for the same mutant. Evidence retains each final result's source run, test log and source hashes. No Core, Simulation or Physics code changed, so there is no official Stryker population for this ticket.

Raw results: 21 killed, 6 survived, 0 timeouts, 0 no-coverage results, 0 build failures and 0 zero-test results. The raw kill rate is 21/27. Two survivors are equivalent for the current layout. Excluding only those two gives 21/25 (84%). Four guard-removal survivors remain explicit test limitations.

