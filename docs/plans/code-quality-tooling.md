# Code quality tooling

Epic ticket: `ter-9gj5`.

This epic adds the checks that keep the code readable: compiler checks of doc comments, reports of complex, long and duplicated code, a docs site, and a cleanup that formats and modernizes the code before every push. The user chose each tool on 2026-10-21, after a comparison of the options, and chose where each one runs on the same day.

## Where each check runs

| Stage | Check | Blocks what |
|---|---|---|
| `git commit` (`.githooks/pre-commit`) | An incremental build of the changed projects and their test projects, with every analyzer | The commit, on an error |
| `git commit` | The tests of the changed code, in Checked | The commit, on a failed test |
| `git commit` | jscpd duplicates, CA1502 complexity and MA0051 length, for the changed lines only | Nothing. It is a report. |
| `git push` (`.githooks/pre-push`) | `tools/cleanup.sh` on the C# files that the pushed commits change | The push, if the cleanup changes a file. The hook commits the cleanup, and the next push sends it. |
| `git push` | DocFX builds the docs site | The push, on a DocFX error |
| Before a merge into main | `tools/test-all.sh`: every test, in Checked and Release | The merge |

The commit hook changes no file and runs only what the commit touches, so that a commit stays fast. The cleanup loads a whole solution, which takes tens of seconds, so it runs once per push instead.

## Decisions

1. The build writes the XML documentation file (`GenerateDocumentationFile`), so that the compiler checks every doc comment: `cref` targets, `param` and `paramref` names, and the XML itself. CS1591 (a public member without a doc comment) stays off until the doc comment rewrite, because 805 public members in `src` have none.
2. `AnalysisLevel` is `latest-recommended`, and `TreatWarningsAsErrors` is on. The root `.editorconfig` turns off each rule that flags a deliberate pattern of this codebase, with the reason in a comment above it. For example, CA1707 (the `_` character in names) stays off in test projects, because test names contain `_`. A deliberate exception in one type is a `SuppressMessage` attribute on that type, with a `Justification`. CS1573 (a `param` tag for only some parameters) is off too, because a doc comment documents only the parameters that need more than their name and type.
3. CA1502 measures the cyclomatic complexity of a method: the number of branches plus one. Its limit is 15, in `analyzers/CodeMetricsConfig.txt`. Meziantou MA0051 measures the length of a method: 60 lines or 40 statements, its defaults. `MeziantouAnalysisMode=None` turns off every other Meziantou rule. Both rules are suggestions, so they never fail a build, and the existing code needs no baseline. After the first cleanup on 2026-10-21, 55 methods were over the complexity limit and 108 were over the length limit, in src, tests and benchmarks.
4. Every compile writes its diagnostics, suggestions included, to `obj/<configuration>/<framework>/analyzers.sarif` (`ErrorLog` in `Directory.Build.targets`). `tools/commit_report.py` reads CA1502 and MA0051 from it and prints each one whose method holds a changed line. It finds the end of a method by matching its braces. An up-to-date project does not compile again, so the file always describes the last compile, whoever ran it.
5. jscpd 5 is a Rust crate. `native/jscpd.nix` builds it from crates.io with a pinned hash, and the dev shell has it. `tools/duplicates.sh` writes an HTML and a console report of the whole code. The commit report prints only the clones in `src/` with a copy that holds a changed line.
6. DocFX reads the compiled assemblies and their XML files, not the source. Thus its own C# parser never meets C# 15 syntax. The site also holds ARCHITECTURE.md, GUIDE.md, tools/README.md, the design docs and the source files. DocFX is a .NET local tool, pinned in `.config/dotnet-tools.json`, because the nixpkgs build cannot start on macOS. `docfx.json` sits at the repository root, because DocFX refuses content outside the folder of its configuration. `tools/docs.sh` builds the site, and it can serve it.
7. The commit hook tests the changed code: a change in `src/Tertius.X` runs every test of `tests/Tertius.X.Tests`, and a change in a test file runs only the test classes in that file. `src/Tertius.Demo` maps to `tests/Tertius.Host.Tests`. A change in `tests/Tertius.Testing` or in the benchmarks only builds. The hook builds only those projects and the projects that they reference, so a change that breaks a project downstream shows in the full run before the merge, not in the commit.
8. The cleanup has two passes, in `tools/cleanup.sh`. First, `dotnet format style` applies the Roslyn modernization fixes that ReSharper does not make: collection expressions, primary constructors, pattern matching, switch expressions, `using` declarations, index and range operators, static lambdas and local functions, readonly structs and members, and more. `.editorconfig` sets each of these IDE rules to suggestion, and the script reads the list from there. Builds do not report them, because a build reports only warnings and errors (decision 14). Then `jb cleanupcode` runs ReSharper's cleanup with every C# task on: syntax style, redundancies, auto-properties, readonly fields, `using` order, member layout and formatting. ReSharper runs last, so its formatting wins. IDE0045 and IDE0046 are off. They turned one more `if` guard into a nested conditional expression on every run, so the cleanup never settled, and a list of guards became a chain of ternaries ten levels deep. Claude turned them off on 2026-10-24, because a list of guards reads better, and told the user.
9. The ReSharper cleanup is the custom profile "Tertius" in `Tertius.slnx.DotSettings`. It is the built-in Full Cleanup, minus the arrangement of arguments, which removes named arguments. `.editorconfig` holds the syntax style and the formatting: modern syntax, `var` only where the type is evident, lines of at most 120 characters, and doc comment text as written. The file layout groups members by kind (constants, static fields and properties, instance fields, constructors, instance properties, everything else) and keeps the author's order inside each group. Static fields and static properties share one group, because a static initializer can read a static property above it. Rider reads both files, so its cleanup gives the same result.
10. The pre-push hook cleans the C# files that the pushed commits change, builds the solution, and commits the result as one commit. Git chose the commits to push before the hook ran, so the hook then stops the push, and the next push sends the cleanup commit too. A file with uncommitted changes stops the hook before the cleanup, so that the cleanup commit holds only the cleanup. The first cleanup of the whole codebase is one commit, and `.git-blame-ignore-revs` names it.
11. The dev shell sets `core.hooksPath` to `.githooks`. Outside the dev shell, a hook runs itself again inside it.
12. The cleanup leaves a `var` local as it is. A collection expression needs a target type, so `var x = new List<int> { 1, 2 }` keeps its initializer, and only a local with an explicit type gets the expression. The user chose this on 2026-10-22.
13. The tests run in the Checked configuration, which has Debug's contracts and Release's optimized code (`Directory.Build.targets`). The commit hook builds and tests Checked, and `tools/test-all.sh` runs Checked and Release. Debug stays unoptimized for the debugger. The user chose a third configuration over an optimized Debug on 2026-10-22. Ticket `ter-a4s2` has the measurements.
14. Every switch over a closed set (an enum, a custom `[Union]` struct or a `closed` record) fails the build when it misses a member (ticket `ter-glx8`, ARCHITECTURE.md "Switches over closed sets"). `CS8524` is off, so an enum switch expression needs no discard arm. `EnforceCodeStyleInBuild` is on with `AnalysisModeStyle` set to `None`, so the build runs only the IDE rules that `.editorconfig` raises: `IDE0010` at error. Every other IDE rule stays a suggestion, which the build does not report, so decision 8 and the cleanup do not change. The user chose IDE0010 on 2026-10-11.
15. The commit report leaves test code out of the duplicates and the complexity, and keeps the length limit for it. A test repeats its setup on purpose, so that it reads on its own, and its branches are its checks. When the report names anything, it ends with a prompt to refactor that code in the same commit, as far as the task allows. So the code improves a little at each change that passes through it, not all at once and not never. The prompt sits in the report and not in CLAUDE.md, so that it appears only at the moment that it applies. The report names every touched method that is over a limit, not only one that the commit made worse. When most of the code is within the limits, the report can name only what gets worse. The user chose this on 2026-10-24.
16. `tools/Tertius.Slop` measures the erosion of `src` (ticket `ter-4jhz`), as the post [Measuring code sloppiness](https://earendil.com/posts/measuring-code-sloppiness/) and SlopCodeBench define it. The mass of a function is its cyclomatic complexity (CC) times the square root of its lines of code (SLOC). The erosion is the mass of the functions with CC strictly above 10, divided by the mass of all functions. A codebase with no functions has erosion 0. The program reads syntax only, with Microsoft.CodeAnalysis.CSharp 5.9.0, so it needs no build and reads all of `src` in about half a second. It prints JSON, because the commit hook will read it (ticket `ter-rnzy`). Its command line is `Tertius.Slop <metric> [root] [--text]`, so that verbosity (ticket `ter-2x99`) becomes a second subcommand beside `erosion`. The rules:
    - The CC is syntactic: 1, plus 1 for each `if`, `while`, `do`, `for`, `foreach`, `catch`, `?:`, `??`, `??=`, `&&` and `||`. A switch statement or a switch expression adds 1 as a whole, whatever its sections, arms, `when` guards and patterns. The code that a section or an arm runs, and the expression that the switch reads, still count. The user chose this on 2026-10-24, because the switch rule (decision 14) asks for one arm per case of a closed set. A metric that counted each arm would punish the code for following that rule.
    - Outside a switch, a pattern `and` or `or` adds 1, like `&&` and `||`. The pattern `x is 1 or 2` makes the same decision as `x == 1 || x == 2`, so a metric that counted only one of them would reward a rewrite that changes nothing. `not` adds nothing, like `!`. Claude chose this on 2026-10-24.
    - A function is a method, a constructor, a destructor, an operator, a conversion operator, an accessor with a body, an expression-bodied property or indexer, or a local function. A declaration without a body, such as an auto-property, holds no code, so it is no function. Code outside any function, such as a field initializer, counts in the SLOC of `src` but in no function.
    - A lambda or an anonymous method counts toward the function that holds it, because it is an expression inside that function's flow.
    - A local function is its own function, and its branches and lines are not in the function that holds it. It has a name and a signature, and a reader reads it as a unit, as a private method. If it folded into its parent, a move of code into a local function would never lower the erosion, while the same move into a private method would. The metric should not prefer one of two forms that read the same. Claude chose this on 2026-10-24.
    - The SLOC of a function counts the lines of its span that hold part of a token: not blank lines and not lines with only comments. Its attributes count, and its doc comment does not. A brace on its own line counts. Each line of a string over several lines counts.
    - The program reads every `.cs` file under `src`, but not the `obj` and `bin` folders, a file whose name ends in `.g.cs`, or a file whose comments before its first code hold `<auto-generated`. It parses with no preprocessor symbols, so the one `#if SYNC_PROFILE` block in `src` is not code.

    On 2026-10-24, the erosion of `src` was 0.364: 89 of 2,772 functions have CC above 10, and they hold 11,945 of the 32,779 mass, in 268 files with 33,633 lines of code. The post measured 0.31 ± 0.17 for established repositories and 0.68 ± 0.20 for code that agents wrote. The heaviest functions are the `AssertInvariants` methods of `EntityTable`, `FrameTree` and `World`, `JoltPhysicsBackend.UpdateGhosts`, `World.PrepareSpawn` and `PhysicsOutputCheck.Run`.
17. `tools/Tertius.Slop` also measures the verbosity of `src` (ticket `ter-2x99`), as the post defines it. The verbosity is the number of lines that a rule flags or that jscpd finds in a clone, divided by the SLOC of `src`. The SLOC is the same as the erosion's. A line counts once, however many findings and clones cover it. The rules:
    - The clone lines come from jscpd, which the tool runs on `src` with the settings of `tools/commit_report.py`: `--format csharp --min-tokens 70 --mode mild` and the JSON reporter. A clone line is a line of either copy of a clone. Without jscpd on the search path, the tool prints a message that names the dev shell and exits with code 2.
    - The flagged lines come from 32 rules that read the syntax with Roslyn, like the erosion. Each rule has an id, a one-line message that says what to write instead, and its source: STYLE.md, the user, or a rule of scb-check (github.com/gabeorlanski/scb-check). One rule, low-use-short-function, also reads where each name of the codebase is used.
    - A finding covers every line of its span, not only its first line. The span is the code that the rewrite removes or replaces, so a try statement of 30 lines is 30 verbose lines and not 1. A rule about a whole function, such as defensive-try-soup-function, flags the statements that it counts and not the whole function. The rest of the function is not what the rule calls verbose.
    - A blank line never counts, inside a finding or a clone. Only comment-repeats-code flags lines that hold only a comment, and those lines count. So the verbosity counts a repeated comment, although the SLOC leaves comments out.
    - The subcommand `all` prints both reports in one JSON, from one parse of `src`. The commit hooks of ticket `ter-rnzy` run it on every commit. It takes 1.2 s, and two separate runs take 1.4 s. Claude added it on 2026-10-24, because the hook needs both numbers for one state of the tree.

    The user's four rules:
    - pass-through-method flags a method whose whole body calls another method with its own parameters, in order. The arguments can have names, as TS0002 asks for a target with more than 3 parameters. The syntax does not show the target's parameters, so the names do not count. It also ports scb-check's trivial_wrapper.py and identity-wrapper-function. An override, an explicit interface member and a method with an attribute exist for their contract, so the rule skips them.
    - single-use-local flags a local whose value only the next statement reads, once. It skips the locals that STYLE.md asks for ("Name the parts of a complex condition"): a `bool` local, or a value that is a comparison, a pattern test or a logical operator. It also skips a value that takes its type from the declaration, such as `new()` or `[]`. A local before a loop keeps its place, because the loop runs the value again. A use in a lambda or a local function keeps it, because the value runs later. A use as a `ref` or `out` argument or as an assigned variable keeps it too.
    - comment-repeats-code flags the line comments right above a statement, with no blank line between. The comment must say what the statement says. Its words are the words of three letters or more, without common words such as "the" or "with", and without a plural s. The statement's words come from its names and keywords. A camel-case name splits into its words, and the code in its blocks does not count. The comment repeats the statement for two or more words, of which at least four fifths are words of the statement. A share of two thirds flagged six comments in `src`. Each of them gave a reason or a fact that the statement does not hold, so Claude raised the share on 2026-10-24.
    - guard-repeats-caller-check flags a null guard on a parameter whose type is not nullable, in a function outside the public API. A null guard is `ArgumentNullException.ThrowIfNull`, `?? throw`, or an `if` that tests the parameter for null and returns or throws. Nullable is on and its warnings are errors, so the compiler already made every caller in the codebase pass a value. A public or protected member and an interface member keep their guards for callers outside (STYLE.md, "Errors and contracts"). A parameter of a type parameter can hold null, so its guard stays. The coordinator suggested a check of the call sites in the same file. That check needs flow analysis of each caller. The compiler's nullable check already covers every call site in every file, so the rule reads the parameter type instead. Claude chose this on 2026-10-24.

    The ports follow STYLE.md where it differs from scb-check:
    - defensive-function-nullable-heavy and guard-repeats-caller-check skip the public API, because a public API keeps guards that are always on.
    - boolean-return-if-else skips the last `if` of a list of guards, because STYLE.md prefers a list of early returns ("Guards").
    - low-use-short-function skips a method whose call is the whole job of a switch arm or a switch section. A state machine of STYLE.md gives each case a method. It also skips a method with an attribute, such as `[Conditional]`, because inlining loses the attribute. scb-check keeps its limits outside the rule file, so the tool uses this project's limits. The function has at most 3 lines, and its caller stays within 60 lines and a CC of 10 after the inlining.

## Not in this epic

- The rewrite of the doc comments. It is its own epic, after this one: a short style guide, then one pass per module, with the docs site and the `cref` checks as guides.
- IDE code style rules in the build. The user decided on 2026-10-21 that the pre-push cleanup modernizes the code and that the build never fails on style. IDE0010 is the one exception, because it is a check of correctness (decision 14). CA1822 (members that could be static) stays off too.
- A gate on complexity and length. The user chose a report on the changed code.
