# Two GPU jobs that send the same commit at once: one job's push fails with 'reference already exists'

Found in t1-stwp on 2026-11-15. Two calls of tools/runpod/gpu_job.py submit by one agent started at the same second, with the same tree refs/scratch/ter-kh4g-1b-layer. Both pushed 1c8fbbdd0 to refs/gpu-jobs/2026-11-15/t1-stwp-cost/1c8fbbdd0. One push won. GitHub refused the other with 'cannot lock ref ... reference already exists', and gpu_job.py ended that job with a CalledProcessError traceback. The job log says 'rejected'. WORKBENCH.md, 'Several jobs at once', tells agents to start such calls in parallel. The hidden ref names the commit, so a push of the same commit to it changes nothing. A fix: after a failed push, look up the remote ref with git ls-remote. A ref that already names the same commit counts as a pushed ref.

## Acceptance Criteria

Two parallel submits of one agent with the same tree commit both send their jobs. A test in tools/runpod/test_gpu_job.py covers a push that fails because the ref already holds the same commit.
