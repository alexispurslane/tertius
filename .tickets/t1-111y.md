# The dev shell has no GC root, so a Nix garbage collection deletes the driver under running tests

On 2026-11-23 at about 02:45 a Nix garbage collection of another session deleted store paths that the dev shell of running agents used: MoltenVK and the blue-noise mask. Nothing roots a dev shell that an agent enters with 'nix develop --command ...', so a collection is free to delete what it references while no process of it runs.

## What it cost that night
- The jamb lead (t1-gout): one run of the Rendering tests failed 1,166 tests with vkCreateInstance ErrorIncompatibleDriver from its first test on. The rerun passed.
- The face cost lead (ter-yglw): two timing runs at 02:47 failed at their start with the same error (kept as x-*-vkfail in docs/research/environment-face-cost/results/).
- The Design X line: the mutant runs of t0-zmjx (Z04 to Z10 failed to build after the collection removed the blue-noise mask) and of t0-rs55 (S12 to S20 ran again).
Each fault looks like a code fault at first, and each costs a rerun of 20 minutes or more.

## The fix that exists by hand
A lead of the Design X line gave its dev shell a GC root, and the back-face line's leads do it in their worktrees with a profile outside the checkout:

    nix develop --profile <worktree>-evidence/nix/dev-profile --command true
    nix-store --gc --print-roots | grep dev-profile

## What is wrong in the system
Every agent must know this step, and a new worktree starts without it. The class of the bug: a tool that a long run depends on can vanish in the middle of the run. To do: make the root part of the workflow that every agent already runs, so that nobody can skip it. Candidates, not decided: the pre-commit hook and tools/test-all.sh enter the dev shell through one profile per worktree; or one shared profile for the repository's flake lock, as tools/runpod keeps /nix/var/nix/profiles/tertius-dev in the container (tools/README.md). Also say in CLAUDE.md's workflow section which form agents use until then.
