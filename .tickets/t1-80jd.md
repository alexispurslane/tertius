# The first run of a card job draws about 10 to 18 % slower per full-size draw, so a comparison of two codes in one job favors the code that runs second

**2026-11-25 · Retired.** Keep the measurement caveat with the old experiments. For a new claim, compare identical settings and cadence, warm both runs, and repeat on the same GPU.

## What was seen

Two card jobs on the RTX 2000 Ada ran the cabin's lamp switch log under the frame-time target of 16.67 ms (render scales 0.5 to 1). In both, the first run of the job rested at a lower render scale with a longer GPU span than every later run.

"Span per full-size draw" is the median GPU span of draws 133 to 192 over the square of the realized scale. It ignores the fixed cost, so it is rough arithmetic of the line orchestrator, not a measurement.

## The reading, not proven

The first run of a job on a fresh worker draws about 10 to 18 % slower per full-size draw. Two jobs are the whole evidence. Variation between workers explains f8b8cba5 as well, and nobody measured a cause (a cold shader cache of the driver, the card's clock, or the worker's start).

## Why it matters

A job that compares two codes runs one of them first. If the first run is slower, the comparison favors the code that runs second, and alternating the runs does not remove it. Under a frame-time target, a slower first run also rests at a lower render scale, which looks like a cost of the code.

## What to do

1. Measure it: one job with four runs of one code. If run 1 is slower than runs 2 to 4 by more than their spread, in two jobs, the reading holds.
2. The remedy to test: each card job starts with one discarded warm-up run of the script that it measures.
3. If the remedy holds, it goes into the job scripts that compare codes (tools/runpod and the survey's cloud scripts), and the README of tools/runpod names it.

## Evidence that needs the same care

Earlier card comparisons of this lab that ran each code once per job, or always in the same order. The Design X line's card evidence is the first case.
