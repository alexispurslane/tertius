# Six Rendering tests fail on lavapipe, on main as on the back-face branch

Found by the acceptance takes of t1-8b4w on 2026-11-21. Outside the epic's acceptance: main d8559eb58 fails the same six tests with the same values, so the back-face layer did not cause them.

The driver: Mesa 26.2.4 lavapipe (llvmpipe, LLVM 21.1.8, 256 bits, Vulkan 1.4.354), the pinned nixpkgs' mesa, on a Runpod CPU worker of 2 processors (tool: docs/research/back-face-depth-layer/acceptance-tools/lavapipe-tests.sh). The whole Rendering project of the branch ran in 4 shards: 3,310 tests, 6 failed, 13 skipped. One CPU job (b64af51d-bffb-4548-bc35-13d3fd192de5-u2) ran the six on both trees, with identical failures:

1. ScreenWalkBoundaryTests.TheShaderHitsTheNextWallPixelOnlyWithinItsSegmentAndStepCap(channel: 3, expected: 1): the walk of a 4-pixel screen segment toward the wall pixel beside it, with a cap of 1 step, returns WalkMiss (2), not WalkHit (1). The other channels pass.
2. HairRenderTests.AHairPixelSendsTheLightThatHairFiberGives(x: -0.6, y: -0.8, z: -4.2, lamp: True): shown <0.09350586, 0.045013428, 0.02192688> against <0.093701534, 0.044884175, 0.021878708>, a difference of 0.000196 against a bound of 0.000183.

4. OutlineRenderTests.TheOverlayDrawsTheOutlineOfEachKindOfFrameOverTheScene: 5 pixels above FLIP 0.1 against frame-outlines.png (largest 0.147).
5. MeteringDrawTests.AStillRightAfterACameraCutAtItsTickShowsTheExposureOfTheNewView: 5.3725805 stops against 5.3883514 +/- 0.01.
6. Fsr3UpscalerTests.TheSettledPatternAndTheFramesAfterAChangeOfTheSceneMatchTheirReferenceImage: 201 pixels above FLIP 0.1 against fsr3-pattern.png (largest 0.320).

Two GpuTimingTests skip themselves on lavapipe, because the frame spans on a shared 2-processor host are too wide to resolve 0.05 ms.
