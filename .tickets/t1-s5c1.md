# ab_run.sh warms only the first tree and reverses the order, which is unbalanced for more than two trees: a tree with a new pass ran 0.44 to 0.56 ms slow in its first run

**2026-11-25 · Retired.** Keep the measurement caveat with the old experiments. For a new claim, compare identical settings and cadence, warm both runs, and repeat on the same GPU.

Found in t1-stwp on 2026-11-15 (docs/research/back-face-depth-layer/stage-1b/cost.md, 'The results on the RTX 2000 Ada' and 'The method'). tools/runpod/ab_run.sh warms the card with one run of the first tree. In the deck and the cabin, the first runs of the two trees with the back-face pass were 0.44 to 0.56 ms slower than their later runs, and the first runs of main and of the tree without the pass were not. Stage 1 saw the same. Also, with four trees the reversed order puts the first tree only at positions 0 and 3 and two others only at positions 1 and 2. Fix: warm every tree once, and turn the order as a Williams square for more than two trees, as the Mac's take of that ticket does.

## Acceptance Criteria

A job of four trees warms each tree, and over four rounds each tree runs once at each position.
